## Scope

**In**

1. **Workspace**: root `Scarb.toml` (workspace, shared versions, `snforge_std` as a
   workspace dev-dependency), `.tool-versions` pinning Scarb 2.19.4 and starknet-foundry
   0.61.0, `crates/hexx/` with its manifest as in §2.1 of the plan (name decided at L-G2;
   `edition = "2024_07"`; **no `starknet` dependency, no Dojo dependency**; `snforge_std`
   under `[dev-dependencies]` only; description and keywords of §2.1), a `lib.cairo` with one
   trivial public item and one test carrying `#[available_gas]`, so that every tool has
   something to run on. `crates/takeover_tests/` as an unpublished member depending on
   `origami_hexmap = "1.8.0"` from the registry, with one test that calls it.
2. **CI** (GitHub Actions, under 10 minutes): format check, build, `snforge test` per
   package, `scripts/check.sh`, the existing link and shell checks kept. Actions pinned by
   commit. No secret in any workflow triggered by a pull request.
3. **Parity tooling**: `scripts/api_parity.py` adapted to `hexx` as §4.2 says (effective
   visibility through `pub mod` and `pub use`; fields, variants and trait members as items;
   the curated `COUNTERPARTS` map winning over the broad exclusion rules; `missing` by
   default), with its unit tests on the cases §4.2 names; the embedded inventory of `hexx`
   0.25.0; `docs/API_PARITY.md` generated (everything `missing` or scheduled, at this stage)
   and `--check` in CI; `docs/EXTENSIONS.md` generated by `--extensions`.
   `scripts/deviations.py` and `docs/DEVIATIONS.md` likewise.
4. **Reference generator**: `tools/refgen/` (Rust, `hexx = "=0.25.0"`,
   `default-features = false`, features `algorithms` and `grid`), the command
   `cargo run -- gen <module>`, one spec and one golden test for a single function
   (`Hex::distance_to` is not yet ported: generate the file and keep it out of the build
   until M1-T2), and the statement in `tools/refgen/README.md` of how CI checks that golden
   files are up to date without a Rust toolchain in the main job.
5. **Gas tooling**: `scripts/bench.py` and `scripts/gas_tables.py` adapted; `gas/*.snap`
   and `docs/GAS.md` generated from the one trivial test; the rule
   `N = ceil(1.05 × measured)` checked by a script that fails when a test has no
   `#[available_gas]` or a budget more than 5 % above its measurement. Say in the report
   whether the snapshot form and the `#[available_gas]` form can be derived from one another
   (plan §4.2).
6. **Class size**: the `consumer` fixture and `scripts/bytecode_size.py check` of the house,
   on the trivial package (plan, R-11).
7. **Publication pipeline, rehearsed and not run**: a workflow triggered by a tag, which
   runs the checks, `scarb package` and `scarb publish`; the token is a repository secret
   that the workflow alone reads. In this task: `scarb package` and, if the installed Scarb
   supports it, a dry run, with their real output in the report; the list of files the
   package would contain; **what the packaged manifest declares for `snforge_std`** (the
   defect of `origami_hexmap` 1.8.0: a dev-dependency in the source, a regular dependency
   for the consumers of the published package; plan §2.1, R-17). Find the cause if it can be
   found without publishing, and write it down.
8. **Answers the plan asks of LIB-04**, each in the report with its evidence: does
   scarbs.xyz accept pre-release identifiers (`0.1.0-rc.1`) (R-3); is the package name still
   free (R-4).
9. `README.md` of the package (what it is, status, how to run the checks), `CHANGELOG.md`
   (form of §9.4 of the plan), `AGENTS.md` at the root in the house style, for the agents of
   LIB-05.
