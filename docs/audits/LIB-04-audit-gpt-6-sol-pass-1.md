# [GPT-6-Sol] Audit — LIB-04 — security and quality

## Verdict

**FAIL.** The workspace and pinned tooling are in place, but the parity table contains false `ported` results, omits public API required by the plan, and can let scheduled work pass a release check. The publication workflow also has no verifiable owner approval gate in this lot. Fix the blocker and major findings before using these gates for LIB-05 or enabling publication.

## Coverage

I reviewed the 36-file `origin/main...HEAD` lot against the brief allowlist; all changed paths are allowed (**AC-9 passes**). The `hexx` manifest has the required name, edition, metadata, no regular dependency, and `snforge_std` only under dev-dependencies (**AC-2 source requirement passes**). `Cargo.toml` pins Rust `hexx = "=0.25.0"` with the required features, `Cargo.lock` records that version and checksums, and `Scarb.lock` records registry checksums. The staged golden file and generator are present (**AC-6 structurally passes**). Staging outside `crates/hexx/tests` is justified until M1-T2; that task must add a gas budget when it activates the golden test. Dropping bytecode attribution is justified until a useful fixture exists.

I ran all 11 parity unit tests, `api_parity.py --check`, `gas_tables.py --check`, and `deviations.py --check`; they passed. I compared the embedded inventory with the pinned checkout at commit `b6b9afb…`, tag `0.25.0`: both contain 452 parser items. Independent parser probes produced the failing cases in findings 3, 6, 7, and 8. Thus **AC-3, AC-4, and AC-5 fail as general tooling guarantees**. The report’s deviations 2–4 require fixes now; deviation 1 is justified and belongs to M1-T2, while deviation 5 can wait for LIB-05.

The CI workflow has `pull_request` and `main` push triggers, read-only `contents` permission, no secret reference, and fixed matrix values rather than untrusted shell interpolation. Its action SHAs match the stated releases for [checkout](https://github.com/actions/checkout/releases/tag/v7.0.1), [setup-scarb](https://github.com/software-mansion/setup-scarb/releases), [setup-snfoundry](https://github.com/foundry-rs/setup-snfoundry/releases/tag/v6.0.0), [lychee-action](https://github.com/lycheeverse/lychee-action/releases/tag/v2.9.0), and [cache](https://github.com/actions/cache/releases/tag/v6.1.0). The publication workflow is tag triggered only and passes the secret only to its publish step; those structural parts of **AC-7 pass**. `git tag --list` was empty locally. Remote releases, repository secrets, tag rules, environment protections, and current PR checks could not be verified because `gh` could not reach `api.github.com`.

I did not run `scarb package`, Cargo builds, or snforge tests for the same write restriction. **AC-8 passes as a reporting requirement:** R-3 and R-4 have dated answers and cited evidence in `REPORT.md`; I could not independently reach the registry pages.
